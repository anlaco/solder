# 07 — Parity contract

> Status: **DRAFT** — pending review
> Normative. It defines exactly what it means for Solder in Rust to
> "work the same" as Solder in Red, and how that is checked.

## 1. The problem

The declared goal of the migration is that the application works exactly the
same. To be able to claim that, an **oracle** is needed: a reference to compare
against.

The natural candidate is the Red implementation running the files in
`examples/`. **It does not work as it stands**, and it is worth saying why
first:

| Problem | Scope |
|---|---|
| The loader corrupts the destination port of the wires | 9 of 14 files |
| The port names in the corpus do not match the registry | The same 9 |
| Files written by hand, not generated by the compiler | 6 of 14 |
| `waveform-demo.qvi` contains a `; TODO: Implementar` and hand-printed values | 1 |
| CI validates compilation on one of the hand-written files | — |

*(Details and verification in [`../whitelist.md`](../reference/history/whitelist.md) §6, §7.1 and §10.)*

**Comparing against a broken oracle produces parity with the defects.** This
document defines how to build a valid one.

## 2. Method correction

An earlier draft of this specification proposed capturing the legacy behavior as
**a prose document**. That is a bad application of the idea it came from:
Michael Feathers' *characterization tests* **are executable tests**, which fail
when the behavior changes. Turning them into prose removes exactly the property
that makes them useful.

> **The parity contract is not this document: it is the files in
> `corpus/`.** This text only explains how they are built and what they
> guarantee.

## 3. What is NOT preserved

Feathers recommends documenting the real behavior *even if it looks incorrect*,
so as not to change it by accident. Here the opposite is done **deliberately and
in writing**: these defects are fixed, and their current behavior is not part of
the contract.

| # | Defect | Rule that fixes it |
|---|---------|----------------------|
| 1 | The loader corrupts the destination port of the wires | Validation on load ([`03`](03-static-semantics.md) §1) |
| 2 | An unknown port returns `number` instead of an error | [`03`](03-static-semantics.md) Rule 1 |
| 3 | TCP refnums are a global singleton: two `tcp-open` share a socket | [`04`](04-dynamic-semantics.md) Rule 14 |
| 4 | `waveform-chart` and `waveform-graph` do nothing even though they are listed as completed | Declared unimplemented ([`04`](04-dynamic-semantics.md) §3.4) |
| 5 | Three different *fan-in* behaviors | [`05`](05-editor.md) Rule 32 |
| 6 | The *fan-in* rule is defined twice, with different signatures | A single function in the kernel |
| 7 | Nothing is validated when a file is loaded | [`03`](03-static-semantics.md) §1 |
| 8 | Cycle detection aborts instead of reporting | [`03`](03-static-semantics.md) Rule 9 |
| 9 | Headless mode does not show the indicators (#50) | A single execution engine |
| 10 | The string control refreshes by itself only after the first Run (#49, GTK-010) | Disappears with the graphics engine |
| 11 | A blocking read operation freezes the interface | [`04`](04-dynamic-semantics.md) Rules 20–20c |

> **Rule 43.** A parity test **MUST NOT** accept any of the behaviors in this
> table as correct. If the captured corpus contains one, the corpus is badly
> captured.

## 4. What is preserved

What defines the identity of the language:

- **The values produced by each VI in `corpus/`.**
- The dataflow semantics ([`04`](04-dynamic-semantics.md) Rule 11).
- That the body of a While Loop runs at least once (Rule 15).
- The indeterminacy of the order between independent nodes (Rule 12).
- Strict type equality, with no implicit conversion
  ([`03`](03-static-semantics.md) Rule 2).
- The visual identity of [`06-visual.md`](06-visual.md).

## 5. Building the corpus

### 5.1 Repair

> **Rule 44.** Each file in the corpus **MUST** be repaired by reading **what the
> `.qvi` says**, not what the loader does with it.

The corruption is in the loader, not in the files: `suma-basica.qvi` does
write `to 3 port: 'a`. The repair is mechanical and lossless:

1. Translate the port names to those of the registry: `out` → `result`,
   `in` → `value`, and the four normalized ones in
   [`04`](04-dynamic-semantics.md) §3.1.
2. Convert to JSON according to [`02-syntax.md`](02-syntax.md).
3. Validate against `schema/qvi.schema.json`.
4. Pass `solder check`: **every file in the corpus MUST be free of
   errors**.

### 5.2 Files that do not go in as they are

| File | What to do |
|---|---|
| `waveform-demo.qvi` | **Exclude.** Its expected values are written by hand and the blocks it illustrates are not implemented |
| The 6 hand-written ones | They go in, but their generated code section **is discarded**: the oracle is obtained by compiling the diagram, never by reading the code they carry |

> **Rule 45.** The oracle **MUST** be obtained by compiling the diagram and
> running it. It **MUST NOT** be read from the pregenerated code section of a
> `.qvi`, which may be out of sync.

*(This is not a theoretical precaution: it is exactly why the loader defect
survived for months. The files were run with `red file.qvi`, which runs the
pregenerated code, so the load path was never tested.)*

### 5.3 Capture

> **Rule 46.** The expected values are captured by **running the repaired Red
> implementation**, with `LC_ALL=C`, and are frozen as versioned files.

The minimal repair of the Red implementation is to fix the loader so that it
assigns each `port:` to its endpoint. It is cheaper than deducing by hand the
values of fourteen files, and it leaves a reproducible oracle.

`LC_ALL=C` is mandatory: GTK-004 documents that the current floating-point
arithmetic **depends on the locale**. Without fixing it, the oracle is not
reproducible even against itself.

## 6. What is compared

> **Rule 47.** The comparison is on **typed values**, not on text.

| Type | Criterion |
|------|----------|
| `number` | Equality with a relative tolerance of 1e-9 |
| `boolean`, `string` | Exact equality |
| `array` | Same length and equal elements, one by one |
| `cluster` | Same fields, same values |

Comparing values and not text prevents the whole corpus from failing because of
a formatting difference —Red produces `"1.0"` where Rust produces `"1"`—, which
is a separate matter and has its own tests.

> **Rule 48.** The presentation format is checked **separately**, with
> specific cases, according to [`04`](04-dynamic-semantics.md) Rule 18.

### 6.1 Acceptable differences

- The **exact text** of error messages.
- The **order** of side effects between independent nodes: Rule 12
  leaves it unspecified, so a parity test **MUST NOT** depend on it.
- The pixel appearance of the canvas. Visual parity is checked against
  [`06-visual.md`](06-visual.md), **not** against screenshots of the current
  editor, which include GTK patches ([`05`](05-editor.md) §2).

> **Rule 49.** Screenshot comparison tests against the Red editor
> **MUST NOT** be used.

## 7. Corpus structure

```
corpus/
├── <nombre>.qvi          el VI reparado, en JSON
├── <nombre>.esperado     valores de cada indicador, capturados
└── README.md             procedencia de cada fichero y qué ejercita
```

> **Rule 50.** Every file in `corpus/` **MUST** declare where its expected value
> came from: captured from the oracle, or derived by hand and why.

## 8. Acceptance criterion

> **Rule 51.** The migration **MUST NOT** be considered complete while any file
> in `corpus/` produces a value different from the expected one, unless the
> difference is justified in writing as one of the corrections in §3.

### 8.1 Minimum coverage

The corpus **MUST** cover, with at least one file each:

- The four scalar types and the two composite ones.
- The three control structures.
- Shift registers and tunnels.
- Sub-VIs and `.qlib`.
- A VI that does **not** compile, for each checkable rule in
  [`03`](03-static-semantics.md): incompatible types, fan-in, cycle, unknown
  port, unconnected input, unassigned case tunnel.

*(The last row is the one that does not exist at all today: there is not a single
test that checks that something **must** fail. That is why none of the eleven
defects in §3 ever raised an alarm.)*
